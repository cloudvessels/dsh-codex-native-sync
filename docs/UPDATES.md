# 自动下载与升级

从套件 `0.3.4-preview.1` 起，完整安装默认启用自动更新。DSH 设置页第五项「自动下载并升级」可关闭；关闭后不开始新的检查或安装，已在下载的文件可能完成缓存，不影响聊天同步。总同步开关和自动升级是独立设置。

## 日常行为

1. 启动 Codex 或已安装本套件的 DSH 时，启动一个本地后台更新器；重复启动只保留一个更新器。
2. 每 6 小时访问一次固定仓库 `cloudvessels/dsh-codex-native-sync` 的 GitHub Releases。只发送普通更新请求，不上传聊天、目录清单或共享库。
3. 选择比已安装版本更新的成套 Windows 包。预览版可接收新的预览版或正式版；正式版不转入预览通道。草稿和旧版本跳过。
4. 校验 GitHub 附件元数据、发布清单、文件大小和 SHA-256，再缓存到 `<运行目录>/.updates/`。ZIP 全部检查通过后才解包；拒绝路径越界、链接、重复项和超限包。
5. 两端窗口、桥接或 DSH 宿主仍在运行时只等待。更新器每 30 秒查看一次退出状态；正常退出两端后安装，不自动关闭或重新打开客户端。Windows 注销/关机会结束后台进程，未安装的包留到下次启动再处理。
6. 安装器更新两个配套组件和 Codex 插件登记，保留原来的共享库、会话绑定、账本、队列和令牌；下次正常打开客户端使用新版。

程序更新不是运行中替换代码，不能承诺全程不退出客户端。若常年不退出两端，下载会完成，安装一直等待。后台更新器以当前用户运行，不需要浏览器长期打开，也不需要 GitHub 登录。

## 第一次升级

`0.3.6-preview.1` 修复 DSH 混合消息漏文字。升级后，带图片的提问和带工具调用的消息会同步其公开文字；图片本体、工具参数/结果和私有推理不在这条文字通道中传输。此前漏掉的文字会在两侧空闲时按原消息 ID 补入，可能一次出现多条，并按补入顺序追加；无需重新导入或清空账本。即使操作同步开关关闭，公开的文字说明仍会同步。

`0.3.3-preview.1` 及更早版本不包含更新器，无法自行获得此能力。先退出两端，下载新版 Windows 包，按原有相同 profile 和运行目录重新执行 `setup.mjs --apply` 和 `--activate`，然后正常打开两端。不要更改数据目录或创建新的空共享库。

仅使用旧 `install.mjs` 或手工复制 DSH 包的部署不会安装后台更新器。必须使用完整 `setup.mjs` 流程。

## 查看或关闭

状态在 `<运行目录>/.updates/status.json`；常见状态：`up-to-date`、`downloaded`、`waiting-for-clients`、`installed`、`failed`。安装记录中的版本是实际安装版本，下载中的版本不等于安装成功。

在套件源码目录运行：

```powershell
node updater/cli.mjs --runtime '<运行目录>'
```

可以用 DSH 第五个开关关闭自动更新。离线关闭可编辑 `<运行目录>/update.json` 为 `{"enabled": false}`。重新启用需要把此值恢复为 `true`，并保持 DSH 开关开启，再启动任一客户端。

## 失败与恢复

网络或校验失败不替换旧版，约 15 分钟后重试。安装出错时使用安装器原有回滚流程；若原文件已有后续修改，会保留并报告冲突。失败版本暂停自动重装，错误记录在状态文件；不要删除真实聊天、共享库或账本来解决升级问题。

排除原因后，可在没有后台更新器占用时运行 `node updater/cli.mjs --runtime '<运行目录>' --apply` 再试。`--retry` 可解除该版本的失败暂停标记，后台更新器下一轮重试。若安装器报告未完成或回滚冲突，先按安装说明处理记录，不强行更新。

压缩包缓存、运行目录旁的 `<运行目录名>.update-stage-<编号>` 解包目录与 `.setup/` 中的备份暂时保留供诊断和回滚，不会自动清理。更新器信任上述项目仓库的维护者；校验用于发现损坏或不一致，不是独立数字签名，也不保证上游代码没有缺陷。

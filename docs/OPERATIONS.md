# 可选操作记录同步

从 `0.3.5-preview.1` 起，在 DSH「设置 → Codex 同步」中可开启第六项「同步 Codex 操作步骤到 DSH」。默认关闭，开关保存后下一轮同步生效，不需要为了切换开关重启。

文字消息仍然双向同步。操作记录只支持 **Codex → DSH**：将 Codex 已持久化的函数/自定义工具调用及其配对结果写成 DSH 原生工具步骤。常见内容包括终端命令、补丁编辑和工具返回文字；不是 DSH → Codex 的操作同步，也不是两个客户端同时执行相同操作。

## 开启与关闭

- 首次启用时从当前记录末尾开始，不倒灌已有操作历史；请在开启生效后再执行要同步的操作。
- 关闭期间不采集新的操作；再次开启不会追溯关闭期间的历史。
- 已完成且待发送的操作队列在本机保留；开启后可以继续补齐。已同步到 DSH 的原生记录始终保留，关闭不会删除它们。
- DSH 正在运行任务时等待，空闲后再写入；断线或进程重启后按队列重试。操作 ID 在同一 Codex 聊天中保持稳定，重复投递不会新增一份相同记录。
- 总同步开关关闭时不发送任何记录，操作开关不会绕过总开关。

## 上下文与显示

开启后，工具调用和结果成为 DSH 会话的一部分，会占用其模型上下文。参数最多保留 4000 字符，输出最多保留 2000 字符，超出部分带截断标记。附件、图像本体和私有推理不参与同步；客户端独有事件、流式片段和仅出现在通知中的内容不保证全部覆盖。

操作以独立的已完成步骤追加到同一条 DSH 聊天，可能晚于所属文字回复显示；不重建原客户端的完整回合顺序或全部轨迹。接收记录不调用模型、不启动命令，也不应用补丁。

记录中的工具声明只用于描述该历史步骤，随后移除；已有请求配置时恢复原配置，没有请求配置的新会话使用外部记录标记，不启动请求。不会将 Codex 工具登记成 DSH 可执行插件。接收记录不等于接收执行指令。

## 故障与维护

Codex 桥接状态文件中的 `syncSteps` 反映当前开关，每条绑定的 `lastOperationError` 单独报告操作同步错误，避免阻断文字同步。队列在账本旁的 `.operations.json`，包含本地操作内容，不要上传到公开仓库。

当前会话重归属维护流程只复制文字。含工具历史的会话会返回 `OPERATION_HISTORY_REHOME_UNSUPPORTED`，保留原会话和绑定，不进行有损迁移。尚未写入工具历史的会话迁移时会同时保留操作队列游标。

旧版需要先完成两侧的配套升级，才能看到和使用这个开关。只把配置中的 `syncSteps` 改为 `true` 不能让旧版获得此功能。
